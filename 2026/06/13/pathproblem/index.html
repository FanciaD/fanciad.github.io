An Ultimate Collection about Path Problems

开点超级大坑，把之前写过的一百个东西合并起来。东西非常多，所以善用目录跳转。

顾名思义，路径问题一般是让你找满足某个条件的最优路径，比如最短路，或者最短瓶颈路（比如MST），等等。

问题本身很简单，但我们有一万个不同的情形。让情况变得更复杂的是，这些情形通常可以 Direct Product 起来：

  1. 无向图 vs 有向图
  2. 非负权图 vs 负权图
  3. 无权 vs 整数边权 vs 实数边权
  4. s-t vs 单源 vs All-Pair
  5. 正常模型 vs 并行算法 vs 动态插入

然后情形就变得复杂了起来。这里将会列举一些我读过/做过的东西。

Minimum Spanning Tree

Undirected

有经典的 \(m\log n\) 算法(Kruskal) 和经典的 \(m+n\log n\) 算法(Prim+Dijkstra)。

但还有一个非常震撼的随机线性算法。

Karger-Klein-Tarjan

人类智慧时刻：考虑随机一半的边递归求最小生成森林，那么这对剩下一半的边有什么用？

显然可以做的是，如果求出了前一半的最小生成森林，那么可以把后一半的边放到上面试一次，看是否它们一定没用。

但这样能干掉多少边呢？可以证明，只会剩下 \(O(n)\) 条边：

我们从小到大考虑每条边，并考虑递归的生成森林。那么有一半概率递归选了这条边，这样就把生成森林里面这两边连起来了。否则，我们考虑生成森林里面有没有把它们连上，如果没有那后半就会剩下一条边。

那么每一步，如果这条边的两端已经在里面连通了，那无论怎样都没有影响。否则，有一半概率它合并，另外一半概率答案加一。因此每个有效操作是，一半概率连通块数量减一，一半概率答案加一。容易发现这样高概率只加 \(O(n)\) 次。

那么，右侧递归就只剩下了 \(O(n)\) 条边。那 \(n\) 太大了怎么办？我们需要一些步骤来减少 \(n\)，因此使用 Boruvka 算法：考虑对每个点找到其最小出边，那么此边必定在最小生成树中，可以进行合并。这样一轮就会让点数除以 \(2\)。

这样递归就是 \(T(m,n)=O(m)+T(m/2,n/2)+T(10n,n/2)\)... 好像差一点。因此做两轮 Boruvka，把 \(/2\) 变成 \(/4\)，然后就是期望线性了。

缩点步骤可以离线 dfs 解决。不过有个问题：如何把后一半的边放到前一半的生成森林上去试一下？这相当于树链 RMQ。这个确实能做，但需要大量数据结构和 Word-RAM 技术......

Note on Tree RMQ

以下部分摘抄自《A Simpler Minimum Spanning Tree Verification Algorithm》。

我们对树做一遍 Boruvka。因为这是棵树，所以是线性的。这个过程中我们可以做一个重构树：每次把一堆点合并起来时，我们加一个点，连向之前的每一个连通块。然后我们希望通过这个过程还原两点间的瓶颈路。首先两点间的路径会形如，每次向上跳到下一个合并的连通块，直到两个点走到一起。考虑在一个连通块内部的过程。因为 Boruvka 每个点都是连出去自己最小的出边，有如下结论：内部两个点间的瓶颈路就是起点终点的最小出边的 \(\max\)，因为中间的边都是越来越小。那么起点的边我们是直接知道的，但终点咋办？因为你要继续往上走，而从终点继续往上的边权不比它的最小出边少，所以我们不用管这件事。

因此有如下结论：在 Boruvka 里面，每次合并一个连通块的时候，我们新建一个点，其向之前的每个连通块连边，边权为这一轮它连出的最小边权。那么，该树上两点的瓶颈路等于原树上两点的瓶颈路。

但这堆东西有什么用呢？搞了这么多，我们现在把树高变成了 \(O(\log n)\)。这样可以做一些事情。我们先求出每个询问的 LCA，然后变成直上直下路径的查询。对于每个点，我们记录它子树里面有多少查询会到这个点往上，以及每一种往上走的距离。那么每个点只需要记录 \(O(\log n)\) 个询问的答案。

假设答案可以 \(O(1)\) 存，那我们每次向下加一个点的时候，只需要二分改一段后缀，然后 Word RAM 一手就可以 \(O(1)\) 修改。每个点从父亲那里拿答案（有一个序列，我们需要取出它的子集）也可以 \(O(1)\) 修改。这里全都是四毛子。注意到每个点的复杂度不超过子树大小的 \(\log\)，所以这是线性的。

但怎么 \(O(1)\) 存答案呢？注意到答案都是这个点到根的路径上的边权，所以实际上可以 \(O(\log \log n)\) 存。满二叉树的情况是简单的：我们只需要记录那条边的深度，然后随便位运算一下就能定位过去。那多叉树怎么办？有一个比上面难了十倍的做法：考虑给叶子递增标号，然后每个中间点的标号是子树内 lowbit 最大的叶子，显然这个唯一。然后，注意到对于子树中的其它点，只要给出这个点的 id 和上面那个点的 lowbit，那我们可以唯一还原出距离这个 id 最近的 lowbit 是这么多的 id，然后就找到了上面那个点所在的链。然后我们对于每个叶子，按照深度记录以它为标号的所有边权。这样，只需要记录深度和 lowbit，我们就可以还原边权。

然后可以注意到，如果一个点需要记录至少 \(\log n/\log\log n\) 种询问，那这样的点一定不多，从而对它们使用 \(\log\log n\) 的复杂度维护是可以接受的。但你需要通过一些步骤保证从大的点复制到小的点的时候是 \(O(1)\) 的。这里做法是，小的点可以维护一些到大的 list 的指针。这个可以通过大 list 的长度和需要的下标提前预处理，而不需要再看大 list 的内容。

原论文甚至有详细实现，有兴趣的可以去陶冶情操一下。

最后是树上 LCA，那按照 OI 惯例先欧拉序转为 +1/-1 RMQ，然后四毛子，\(O(\log n)\) 分块后块间 ST 表，块内枚举所有情况暴力。

Directed

Classic Algorithm

Directed MST（或者叫做最小树形图）的经典算法不是显而易见的，所以这里先讲一下。

可以参考 OI 教程。

Chu-Liu Algorithm / Edmond Algorithm

最小树形图相当于，对除去根外每个点选一条出边，使得没有环。（选出边还是入边看问题定义，但是等效）

我们考虑对每个点找到它的最小出边，那么这构成了一个内向树森林。先考虑只有一棵内向树的情况。如果此时根在这个环上，那么就做完了：把指向环的边删掉，则得到的显然是最小树形图。那如果根在外面呢？可以证明，此时最优解中这个环一定只取了一条向外的出边（从而剩余部分沿着环走）。原因是，如果取了多于一条，那因为环上是最小出边，所以不如把其中的一些接到环上。

此时可以做如下变换：把环缩成一个点，然后对于这里的每条出边，将其边权加上（环的边权减去环上指向这条边起点的边权），表示选了这条出边就会沿着这里把环上剩下的边选了。那么刚才那样就说明了如果根在外面，那么答案不变；而如果根在里面，那答案就是以缩点后为根的最小树形图，加上环上除去到它的边的边权和。

一般情况下上述证明也对。然后重复这个过程即可。最后可以通过缩点的过程还原答案。

直接做是 \(O(nm)\) 的，然后有一个来自 Tarjan 的更快算法：

Tarjan's Algorithm

考虑从一个点开始 dfs，每次走最小出边。如果走出了一个环，那就沿用之前的讨论，把环缩成一个点，把出边合并起来，然后继续走。直到把整个图缩成一个点。

对，这就做完了。复杂度取决于如何合并出边。如果用 OI 经典的线段树合并，那就是 \(O(m\log n)\)，但好像也有 \(O(m+n\log n)\) 的做法。

参考练习：[IOI 2021] Keys, [JOI Open 2019] Virus Experiment

Bottleneck Paths

找到从 \(s\) 到 \(t\)，最大边权最小的路径。

无向图的情况抄个无向图 MST 就秒了，所以我们只看有向图。

有向图的情况显然有 \(m+n\log n\) 的 Dijkstra 类做法。那能不能更好呢？

Directed, s-t: Dividing the Weights

m log*n Algorithm

Gabow, Tarjan，《Algorithms for two bottleneck optimization problems》

我们考虑二分答案。每次我们将当前区间所有边分为 \(k\) 份，然后尝试找到答案在哪个区间。每次把边权更大的边删了，边权更小的边当作一直存在。

如果我们已经将边按照边权从小到大分成了 \(k\) 份，那接下来只需要，不断加边，问什么时候 \(s\) 能到 \(t\)。那就维护一个 search，每次加边如果能到新的点就继续搜。显然总复杂度 \(O(m)\)，那么只需要考虑如何分成 \(k\) 份，以及需要递归几次。

Median Computation

经典算法问题：找中位数 (k-th)。

把每五个元素分成一组然后排序，每组取出中位数，递归算这 \(n/5\) 个数的中位数。

此时，一定有 \(3n/10\) 个数比这个中位数大（\(n/10\) 组，每组三个），也一定有 \(3n/10\) 个比这个小。那么，我们判断一下答案在哪边，然后递归另外 \(7n/10\) 个。这样 \(T(n)=O(n)+T(n/5)+T(7n/10)\)。所以是线性。

图示：标 \(b\) 的都比中间大，标 \(s\) 的都比中间小。

那么分 \(k\) 块的复杂度是 \(O(m\log k)\)。注意到每一轮后这个 \(m\) 会除以 \(k\)，因为这里是当前区间内边数（但搜索还是总边数）。因此，第一轮 \(k\) 是常数，后面每一轮 \(k\leftarrow 2^k\) 都行。因此复杂度是 \(O(m\log^* n)\)。

m beta(m,n) algorithm

《Bottleneck Paths and Trees and Deterministic Graphical Games》

能不能不要 \(m\log k\) 呢？考虑直接随机选 \(k\) 个点出来当分界点，那么高概率每一段是 \(\frac nk\log\) 的。但问题是，我们不知道别的边都在哪一段。此时怎么求出答案在哪一段呢？我们可以小心一点，就不需要对于每条边都求出它在哪一段，而只做需要的工作。

之前的问题还有一个做法：我们把边权放到 \([1,k]\) 的段后，跑一个 Dijkstra，每次更新下一个瓶颈路最小的点。由于权值只有 \(1\) 到 \(k\)，我们开 \(k\) 个队列维护，这样就是线性的。现在，我们不再一开始就把边权放到 \([1,k]\)，而是更新点的权值的时候再看：我们对每个点维护前面到它的最小瓶颈路，然后维护这个值在哪一段里面。每次更新一个点的距离的时候，如果它所在的段变小了，那我们暴力向下枚举。这样更新次数就是 \(m+nk\)。

那我们第一轮跑 \(k=m/n\)，后面用之前的方式。这样的话，复杂度是最小的 \(i\) 满足 \(\log^{(i)} n\le m/n\)。这东西就被叫做 \(\beta(m,n)\)。注意到 \(m=n\) 这个就是 \(\log^* n\)。

Lazy Binary Search

上面还可以做到更好：我们实际上可以做到 \(m+n\log k\)。虽然这样并不能降低这个算法的复杂度。

实际上如果一个值很大，那我们没必要现在就把它具体在哪一段给求出来，可以等我们到那了，或者等那个值变小了，我们再求。

比如说，考虑把值分成 \(\sqrt k\) 块，先只更新它在哪个大块内。当我们 Dijkstra 的距离搜到某个大块时，我们再把在这一块内的那些距离具体地算出来，之后具体地更新这些值。注意到，如果一个点需要被具体更新了，那它的距离最后就在这一块内了，所以每个点只会这样干一次，复杂度就变成了 \(m+n\sqrt k\)。

然后把这个变成二叉搜索树（或者线段树），每个点表示一段值域，叶子对应那 \(k\) 段，然后上面每个往下平分。我们记录当前搜到的距离在线段树上的路径。更新一个权值的时候，我们往下走，走到和那个路径分离的子树就停下。然后直到更新了一个比子树更小的权值，或者当前距离到了这个子树再继续。这样不会往上走，所以复杂度是 \(m+n\log k\)。

Directed, Single-Source: More Careful Recursions

和之前的区别在于，如果我们想要对于每个点都求出 \(s\) 到它的瓶颈路的话，在二分 \(k\) 段之后，我们就不能只走 \(t\) 所在的那一段，而是得每一段都继续递归。这样的挑战是，每一层的问题总大小不会变小，所以即使你 \(n\log k\) 的代价把单个问题大小减小了 \(k\)，那总复杂度还是 \(n\log n\)，所以这样不行。

仔细看一下之前的过程。我们访问一个点，枚举它的出边的时候，如果边权在同一段或者更小，那我们直接确定了下一个点也在这一段（如果它还没有被访问），那么可以直接把它拿过来。否则，我们暴力 \(O(\log k)\) 更新下一个边权。那么，我们需要给一条边 \(\log k\) 的代价当且仅当它满足下面这个形式：到这条边起点的瓶颈路小于（在分 \(k\) 段时）这条边的边权。

这有什么用呢？考虑分治的步骤。求出从 \(s\) 出发，到每一个点的瓶颈路在哪一段后，我们对每一段内的点继续分治。此时，瓶颈路更小的点可以看成直接可达，那么可以把那部分合并到一个点；瓶颈路更大的点一定不可达，那么可以删掉。这样递归时每个点只在一个递归内部。然后可以发现，这一段中边权在更大的段的边也可以直接删掉，因为显然没用。那么，上面我们分析出来需要 \(\log k\) 代价的边要么是从一个瓶颈路更小的点连到更大的点（不同区间），从而需要被缩起来，要么是一段内一条边权大于这一段的边，从而可以直接删掉。如果我们不考虑缩起来的情况，那就是说每条边只会这样一次，从而总的复杂度就是 \(m\log k\)，即使有很多层递归也一样。

但缩点后跨层的边不会消失，而是会变成递归问题中起点到其它点的边。这一部分还是困难的，如果暴力做这 \(n\) 条边，那就还是 \(n\log k\)，这是不能接受的。怎么处理这些呢？我们可以再次考虑 charge 到不同层的边上。不妨假设图连通。我们先做权值最小的一段，然后考虑一个已经访问到的点和它的没有被访问的相邻点。此时那个点一定不在这一段，从而我们可以把对起点到这个点的边的 \(\log k\) 代价统计到已访问点连到这里的边上，这样就把代价摊还掉了。但这样可能中间没访问到的点还有起点到它距离更小的边，所以你得把中间扫一遍，这个 \(n\) 的代价就爆炸了。

如何避免这个 \(n\) 呢？我们把图分成很多大小 \(\log k\) 的连通块，然后每一块做上面的东西。具体来说，如果我们做某种权值的时候用到了这一块，那我们就去把剩下没有访问的点扫一遍，找到里面起点到它们最小的一条边，\(\log k\) 找到这个边权在哪一段，然后把在这一段内的边都拿出来下次用。这整个过程只需要 \(\log k\)。注意到每做一次都意味着这一块里面有一种距离，然后因为这是连通块，所以 \(k\) 种距离会有 \(k-1\) 条可以统计代价的边，这就没有问题了（预处理是 \(n/\log k\cdot k\) 的）。分块可以找个生成树然后树分块。

这样复杂度是 \(m\log k\)（递归中删掉的边的代价）加上 \(m*\log_k m\)（递归深度）。取 \(k=\exp(\sqrt{\log n})\)，这是 \(m\sqrt{\log n}\) 的。
