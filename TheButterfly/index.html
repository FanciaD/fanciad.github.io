Parallel Reachability

问题是这样的：给一个有向图，我们想算连通性（比如，给一个源点）。

这里希望算法是并行的。但我们都知道，这东西已经在 里面了，做法是矩阵乘法然后快速幂。

所以还有一个要求是 efficient。这里指即使并行，总共的 work 还是 的。

但另一方面，这里的 Efficiency 是困难的，这在一般分治里面是简单的。这里不同的是，好像很多分治步骤根本不会有一点进展。唯一有进展的只有 Bridges 的情况。那么，我们为什么会经常到 Bridges 的情况？

这样想好像根本看不出来为啥，因为可能就是没有。那换个想法：注意到 Remainings 没有一点代价，实际上 dfs 的时候根本走不到那里，因此这种情况也是不差的。那换成是说，我们希望不是一直走单纯 Ancestor 或者 Descendant 的情况。

Parallel Version

为了做到并行，我们需要几步改进：

Bound-Hop search and Fringes

首先 dfs 是需要 n 个深度的。无向图 dfs 有一些高论，但有向图不知道。

一个减少深度的方式是，直接只搜 个深度。这样自然就解决了深度太大的问题，但这样搞不一定对：之前的关键性质是，每条路径分治完只会分出最多两份，原因是如果能到一个点，就能到后面的所有点。但限制深度后显然不一定有这件事，甚至可以一条路径被完全分开——假设距离是 循环。

为了避免这件事，考虑如果加入了一个点，就把它后面若干步的点复制进来——这些点被称为 Fringes。这样的话，它们可以帮助这个路径不被分开，但同时它们也保留在原图内继续递归。

考虑直接把向后 的东西拿进来。这样之后，每一个 步的路径都可以有进展（像之前那样，就是进展到 ）。那么，令 略大于 的话，每次一个很长的路径可以变成相对短的路径（考虑每一段），最多 轮就可以变成 。可以想象的是，这样的并行深度可能也是 。

但每次多拿一些点，显然会导致递归复杂度增加。我们希望每次加进来的足够小——例如只有 倍，从而递归 层完全不影响。如何做到 步不影响事情呢？首先如果每个深度的点数是均匀的，那这是简单的：如果深度小于 我们就直接不做了，否则复制一段就只有 的占比。一般情况呢？我们随机一个距离做，期望就是对的。

最后有个小问题：递归的话，我们希望每次搜的距离不增，不然可能全乱了。因为这里有个随机，所以给每一层一个距离区间，总共就多 倍。

此时还有一些问题：例如，我们的证明依赖距离随机，但一条路径和当前选择点的关系可能与随机有关。为了避免这个，其一是分类的时候按照距离区间的上界分，其二是势能分析的时候可以发现有一定概率划分的东西不影响这事，但我没有发现明白。

Parallel Search

现在又有了一个算法，它只需要 深度的 dfs。但这还不是并行的，因为你需要每次选一个点开始 dfs。虽然理论上我们在分开递归，但可能剩下一些没有被访问到的点，这部分深度可能是 。

为了避免这些一直访问不到，考虑一起搜——但这样直接每个点访问太多次。而我们希望的是总 Work 是 m polylog 的（不然直接矩阵乘法）。

那么有一个优秀的方式：倍增地访问。具体来说，我们让每一轮访问的点数是上一轮的 倍，这样的话，考虑每个点第一个被访问的轮，它在这一轮被访问但不在上一轮被访问的话，期望访问的次数就是 级别的。原因就是考虑在这一轮里面随机了很多去到前面的轮。

Another Improvements

之前分析的核心是说，如果我们随机一个点它能碰到路径（假设就是 a 类），那分出两个有关的子问题，此时 a 类点数量期望减半，b 类点数量不会增大（可能还有 y 类变成 a/b 类，但这里不讨论这些细节。）

那如果随机 个点碰到路径呢？可以发现 a 类点数量此时就是 。我们只需要魔改一下上面的证明：考虑任意 个 a 类点，想象其中选了 个，然后我们判定剩下那个是否还是合法的。维护它们之间互相是否可达的关系，首先如果有一对双向可达，那直接被当作 bridge 删掉了，因此不会存在。然后 a 类点是能到路径的一部分，但不能反过来；所以如果有一个点能到达别的点，那它的标记就和路径上的标记不一样，因此会分开。再考虑那些出度是 的点，这些点不能相互到达，所以一个这样的点的标记里面，别的都不能到达它。但路径上每个点的标记是前面一些点能到它，从而只有最早的一个可能还合法（相同位置进去都不合法）。这说明，固定 个点，随机选 个后，只有一种情况剩下那个合法。然后数数一下就知道总的期望是 。

然后还需要考虑两边，此时可能大概还是 。（但下一篇的分析又是按照 做的，我不理解）。这样的话，每次分 段，但除以 ，取 就是 且 work-efficient 的。

对于有多个点开始的实现，考虑每个点把 B 删掉，然后按照 A/D 分类。然后把多个点的 A/D 关系放一起分类。因为路径上每个点都只是一段前缀的 D（或者另外一种情况），因此只是分成了 段。

然后考虑上 parallel。那么限制 hop 数，搞一套 fringe 过来。Fringe 被别的点划分可能有点麻烦，这里的写法是每个点的 fringe 里面复制递归一次，然后原先的部分一起做多划分。然后把需要做的随机距离使得 fringe 不大再做一次，同时还有保证递归的时候 hop 数递减。

还有个问题：怎么保证每次每条路径被碰到了 次，而不是很少的次数？和之前一样，一种方式是 倍倍增地随机选点，这样第一轮碰到的时候期望就是 个左右。

然后这个分析就变得非常复杂了。可以证明说，按照上面的方式，给每个点随机一个深度，然后开始递归，则每一层后，每个点涉及到的点数会差不多除以 。这大概和上面那个除以 的证明差不多。然后我们可以说明，直接这样分在每一层上都是合理的递归。

Distance Shortcut / Hopsets

现在我们不仅希望可达性，还希望求出一个距离。这里有一个近似做法。

直接用可达性做法的问题是，本来 就可以还原 的可达性了，但如果是最短路的话，这样可能就绕路了。因此我们希望不绕太多路。

第一种想法是，考虑每次限制一个距离，然后搜的时候不仅限制 hop，还限制距离。那么绕路就只会绕这么多。如果我们知道到这里每段路径差不多有多长，那设这个限制既不会搜不到一小段路径，也不会绕更多。

估算路径长度只需要总长度除以期望到这里分出来多少个问题。如果有太长的，可以分析的时候给它分个段，这不会增加问题数。

这样的话每层都是+常数倍。所以最后近似比是 倍，但不排除也可能是常数倍（每一段分析）。

然后咋更小呢？如果限制更小的距离，那我们只能覆盖路径的一部分。在更下面的层里面，我们确实是这样做的：那里有很多个子问题，每个部分里面找到的点都只绕了很短的路。如果我们把那些点拿过来，放在更大的层上算 shortcut，我们就能得到更好的近似——这些点被称为 shortcutter。

根据之前的分析，每往下分 倍，路径长度大概就除以 。所以如果我们想要 的近似，就需要往下到 倍那么多层，因此最后复杂度也乘上 。

我们来重新考虑一下——以第一层为例，如果这一层选了一个点作为 bridge，那么误差是 级别的，这不大好。那么为了弥补这一点，我们需要误差 的点来作为 bridge……

这里有一个细节问题：我们说明这个合法的方式是，如果它是 bridge，那么它在 层上面是shortcutter。但可能对于前几层，就没有上面这么多层，然后就说不下去。

因此考虑空出这么多层：第一层直接从 距离开始搜，然后把前 层的东西放到第零层——距离 的部分上面跑 shortcut。这样就避免了这一问题。作为代价，实际上它的复杂度是除以了两个 ，也就是 的。
